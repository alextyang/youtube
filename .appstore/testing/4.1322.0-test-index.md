This is the release-blocking test contract for App Store Connect build `1331`.
It covers the processed Safari build, every interactive feature exposed by the
settings UI, every current Jest assertion, and the cross-feature conditions
that source-level tests cannot prove.

Companion indexes:

## One-command Safari test

Run the complete fail-closed test from the repository root:

```bash
./scripts/appstore/safari_full_test.py
```

The command performs a clean Safari conversion/build, all source tests, lint and
dependency audit, index coverage checks, signed-artifact inspection, live App
Store Connect verification, and manual-ledger validation. It exits nonzero for
any failed automatic assertion, missing manual result, `NOT_RUN`, `BLOCKED`, or
unjustified `N/A`.

Create the release's manual evidence ledger once:

```bash
./scripts/appstore/safari_full_test.py \
  --init-manual .appstore/testing/results/4.1322.0-1331.json
```

For fast mechanical iteration, `--quick --automated-only` skips the clean
rebuild and manual ledger while retaining signed-artifact, App Store, resource,
permission, signature, entitlement, inventory, locale, and crypto gates. This
mode is diagnostic only and cannot authorize publication.

## Status and evidence rules

Use only `PASS`, `FAIL`, `BLOCKED`, or `N/A`. `N/A` requires a written reason.
Each manual result must record the tester, date, macOS version, Safari version,
hardware architecture, account state, settings profile, exact YouTube fixture
URL, and screenshot/video/console evidence. A result from another browser does
not satisfy a Safari assertion.

## Publication exit criteria

Do not publish until all of the following are true:

1. `RES-01` and every Priority 0, artifact, signing, permission, privacy, and
   App Store assertion is `PASS`.
2. All 113 indexed automated assertions, lint, production dependency audit,
   Safari conversion, Release compilation, archive/signature checks, and App
   Store processing pass for the exact candidate commit/build.
3. Every one of the 452 indexed controls has passed its component profile on
   `ENV-01`; each high-risk category has passed its category assertions and
   required environment/fixture matrix.
4. Upgrade testing from 4.1321.0 shows no settings or stored-data loss.
5. There are no open severity-0/1 defects. Any accepted lower-severity defect
   has an owner, user impact statement, workaround, and explicit publisher sign-off.
6. App Store metadata, privacy answers, export-compliance answer, support URL,
   screenshots, and the customer release notes describe the tested build.
7. The selected App Store build is exactly `4.1322.0 (1331)` and submission is
   a separate, deliberate action after this ledger is signed off.
